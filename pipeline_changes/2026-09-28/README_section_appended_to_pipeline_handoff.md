
## 2026-09-28: weekly-sweep defect fixes (parsers.key, weekly_sweep.py underwrite, fix_defects_0928.py; applied from the cloud session with Najum's approval)

- What was fixed. The two defects the 9/21 run logged (Weekly sweeps log, note of 2026-09-21) plus one the fix uncovered:
  1. Address matching. `parsers.key()` now folds the portal spelling variants before comparing: Mount -> mt, Fort -> ft, Saint -> st, Terrace -> ter, Parkway -> pkwy, Highway -> hwy, Trail -> trl, Square -> sq, North/South/East/West and their compounds -> n/s/e/w/ne/nw/se/sw. `parsers.py` is read by the local stages and by `sweep_remote.py` in the workbench, so both sides now agree on the key. A scan of the seen index found exactly five pairs that were the same property under two spellings (420 and 827 Mt/Mount Vernon Ave Portsmouth, 749 Mt/Mount Airy St Petersburg, 1025 W/West End Blvd Winston-Salem, 210 Raleigh Road Pkwy/Parkway N Wilson) and no other collisions.
  2. Same-date re-score. `weekly_sweep.py underwrite` keeps a street-keyed map of file 14; when a row's event starts with "weekly sweep <today>" and contains UNREVIEWED, a rerun (normally the one after the step-8 constants lookup) rewrites that row's price, status, event, score, coc, dscr, novice, crime, drive_wb, flood, why, note and url instead of printing "already in file 14"; i, drive_ec and historic are kept. The step order in the task prompt no longer matters: underwrite, add constants, underwrite again gives the constant-aware scores. The memory note of 9/21 ("ALWAYS run the constants lookup BEFORE the first underwrite") is now unnecessary but harmless.
  3. The `i` column. file 14 is written with a byte-order mark, so `rd()` reads its first field as "\ufeffi"; the fold wrote the row under "i" and `extrasaction="ignore"` dropped it (that is why the 9/21 rows had a blank i until the advisory passes assigned w5 and w6). Underwrite now writes the first field by its actual name and numbers new rows w<n+1> from the highest existing w<n>.
  4. Tally. `folded_into_14` for a date is now the count of file 14 rows whose event starts with "weekly sweep <date>", whichever pass folded them; a rerun used to write the latest pass's count (0).
